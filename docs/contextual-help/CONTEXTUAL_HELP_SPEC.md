# GymPlanner — Contextual Help System

## Назначение
Сложный интерактивный onboarding-тур заменяется простой контекстной системой помощи. На основных сложных страницах размещается единая кнопка `?`, открывающая подробное руководство именно по текущему разделу.

Основной принцип: **помощь должна быть доступна тогда, когда она понадобилась пользователю, а не только во время первого запуска.**

## Основная концепция
Примеры:
- `Сегодня → ? → руководство по текущей тренировке`
- `Тренировки → ? → создание и настройка тренировок`
- `Прогресс → ? → графики и статистика`

Кнопку не требуется добавлять на очевидные или технические страницы.

## Отказ от старого onboarding
Отказаться от:
- последовательных spotlight-шагов;
- обязательного прохождения;
- `Назад / Далее`;
- автоматической навигации;
- сложного DOM-targeting;
- перемещения персонажа между UI-элементами;
- ветвлений старого onboarding.

Legacy-код удалять только после проверки зависимостей.

## First Help Hint
Когда новый пользователь впервые попадает на страницу с `?`:
1. страница полностью загружается;
2. интерфейс затемняется;
3. `?` остаётся подсвеченным;
4. появляется короткое сообщение о том, что здесь находится руководство;
5. пользователь закрывает подсказку;
6. сохраняется глобальный `HasSeenHelpIntroduction = true`.

Подсказка показывается только один раз глобально, а не на каждой странице.

## Help Button
Создать переиспользуемый `HelpButton`, который:
- соответствует дизайн-системе GymPlanner;
- имеет hover/focus/pressed состояния;
- доступен с клавиатуры;
- имеет корректный `aria-label`;
- работает на Desktop и Mobile;
- открывает руководство текущей страницы.

## Help Dialog / Help Sheet
На Desktop использовать крупный modal/dialog. На Mobile — full-screen или near-full-screen Help Sheet/Page.

Руководство должно поддерживать:
- заголовки;
- структурированный текст;
- иллюстрации;
- персонажа;
- несколько секций;
- прокрутку.

## Структура руководства
Каждое руководство разбивается на логические секции. Например, для тренировок:
- создание тренировки;
- добавление упражнения;
- настройка подходов;
- изменение веса;
- замена упражнения;
- суперсеты;
- другие актуальные функции.

## Прогресс
Для графиков объяснять:
- что показывает график;
- источник данных;
- оси;
- выбор периода;
- выбор упражнения;
- интерпретацию изменений;
- показатели прогресса.

Сложные графики обязательно сопровождать иллюстрациями.

## Иллюстрации
Сложные действия обязательно сопровождать визуальным объяснением:
- актуальные скриншоты;
- фрагменты UI;
- схемы;
- стрелки;
- подсветка элементов;
- обучающие иллюстрации.

Иллюстрация должна объяснять действие, а не быть декорацией.

## Персонаж GymPlanner
Персонаж остаётся частью Help System, но не управляет навигацией.

Использовать только существующие утверждённые изображения персонажа. Новые варианты не генерировать.

Разрешается:
- crop;
- удаление пустого пространства;
- прозрачный фон;
- уменьшение;
- увеличение без заметной потери качества.

Запрещается менять лицо, тело, одежду, цвета, стиль, логотип или структуру персонажа.

Существующую эмоцию/позу выбирать интуитивно по контексту.

## Архитектура
Разделять:
- `HelpButton`;
- `HelpDialog / HelpSheet`;
- данные руководства;
- изображения;
- пользовательское состояние.

Не хранить большие инструкции внутри универсального UI-компонента и не копировать Help Dialog между страницами.

## Масштабируемость
Добавление новой функции должно требовать только добавления соответствующего Help Section с текстом и иллюстрацией, а не изменения архитектуры Help System.

## Дизайн
Сохранять существующий визуальный язык GymPlanner:
- тёмную тему;
- зелёные акценты;
- скругления;
- typography;
- spacing;
- дизайн-токены.

## Mobile
Проверить safe area, scroll, изображения, текст, touch targets, кнопку закрытия и отсутствие horizontal overflow.

## Accessibility
Кнопка помощи должна иметь accessible name. Modal/Sheet должен корректно работать с focus, keyboard navigation и semantic headings.

## Состояние
Хранить только необходимый признак знакомства с Help System, предпочтительно `HasSeenHelpIntroduction`. Не создавать сложный tracking прохождения инструкций.

## Актуальность
После изменения функциональности страницы проверять соответствующее руководство. Устаревшая инструкция считается UI/UX-багом.

## Критерий завершения
Система готова, когда:
- старый обязательный onboarding больше не нужен;
- `?` доступен на выбранных страницах;
- открывается правильное руководство;
- есть текст и иллюстрации;
- Desktop и Mobile работают;
- First Help Hint показывается один раз;
- состояние сохраняется;
- руководство можно открыть повторно;
- новые Help Sections добавляются без изменения архитектуры.
