# GymPlanner — Help Content Guide

## Назначение
Правила создания текстов, иллюстраций, скриншотов, персонажа и структуры встроенных руководств GymPlanner.

## Основной принцип
Пользователь открывает руководство, чтобы быстро понять конкретную функцию. Не превращать Help в техническую документацию.

Каждый раздел должен отвечать на практический вопрос:
- Как создать тренировку?
- Как добавить упражнение?
- Как изменить вес?
- Как создать суперсет?
- Что показывает график?
- Как посмотреть прошлый результат?

## Структура секции
Предпочтительно:
1. название действия;
2. короткое объяснение цели;
3. иллюстрация;
4. короткие пошаговые действия;
5. при необходимости — важное условие.

## Иллюстрации
Для сложной функции использовать минимум одну иллюстрацию.

Она должна соответствовать реальному актуальному UI.

Разрешается выделять:
- кнопку;
- карточку;
- поле;
- график;
- переключатель;
- область интерфейса.

Можно использовать рамки, стрелки, мягкую подсветку и номера шагов.

Не перегружать одну иллюстрацию большим количеством указателей.

## Текст
Писать коротко, понятно и разговорно. Не использовать ненужный технический жаргон.

Плохо:
> Произведите инициализацию новой сущности тренировочного шаблона посредством соответствующего элемента управления.

Хорошо:
> Нажми «Создать тренировку», чтобы добавить новый шаблон.

## Пошаговые инструкции
Если действие состоит из нескольких операций, использовать короткие нумерованные шаги.

Не создавать 15 шагов там, где процесс объясняется тремя.

## Персонаж
Персонаж — помощник и часть визуальной идентичности GymPlanner.

Не размещать его возле каждого абзаца.

Использовать:
- в начале руководства;
- перед важным советом;
- при сложном объяснении;
- в конце;
- в подходящих help states.

Использовать только утверждённые существующие изображения.

## Эмоции и позы
Выбирать существующее изображение по смыслу:
- приветствие → дружелюбный;
- демонстрация → указывающий;
- сложный момент/аналитика → задумчивый;
- необычная функция → удивлённый;
- завершение/полезный совет → позитивный.

Это рекомендации, а не жёсткая таблица.

## Тренировки
Руководство ориентировочно объясняет:
- назначение страницы;
- создание шаблона;
- добавление упражнения;
- количество подходов;
- вес каждого подхода;
- редактирование;
- удаление;
- замену упражнения, если функция существует;
- суперсеты;
- типы подходов, если функция существует;
- другие актуальные возможности.

Не описывать функции, которых ещё нет.

## Сегодня
Ориентировочно объяснить:
- содержимое страницы;
- начало назначенной тренировки;
- отметку выполненных подходов;
- изменение значений во время тренировки;
- завершение;
- результат завершения;
- пропуски, если поддерживаются;
- замену упражнения на сегодня, если поддерживается.

## Прогресс
Для каждого графика объяснить:
- что он показывает;
- откуда данные;
- горизонтальную ось;
- вертикальную ось;
- выбор периода;
- выбор упражнения;
- интерпретацию результата.

Графики обязательно сопровождать иллюстрациями.

## История
Описывать раздел именно как историю тренировок, а не как блокнот.

Объяснять:
- какие тренировки сохраняются;
- какие данные доступны;
- как открыть прошлую тренировку;
- как сравнить результаты, если функция существует.

## Актуальность
После значимого изменения UI проверять связанный Help Content.

Если скриншот устарел — заменить.
Если название кнопки изменилось — обновить текст.
Если функция удалена — удалить секцию.

Устаревшая справка хуже отсутствующей.

## Что не делать
Не:
- описывать очевидное ради объёма;
- писать длинные вступления;
- повторяться;
- использовать устаревшие screenshots;
- придумывать функции;
- использовать персонажа вместо полезной иллюстрации;
- превращать руководство в обязательное обучение.

## Критерий хорошего Help Section
После просмотра секции пользователь должен понимать:

**что это → зачем это → где это → что нажать → какой результат ожидать**
