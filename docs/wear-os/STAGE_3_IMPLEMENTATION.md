# Wear OS — Этап 3: API подключения устройства

## Выполнено

Реализован полный серверный цикл подключения часов: создание одноразового кода,
pairing, выдача отдельных watch credentials, атомарная ротация refresh token, список
устройств и отзыв устройства. Добавлены отдельные authorization policies для
main-app management и будущих запросов от watch identity.

Контракты и endpoints описаны в [API.md](API.md), модель безопасности и жизненный
цикл credentials — в [PAIRING.md](PAIRING.md).

## Безопасность

- коды случайные, короткоживущие, single-use и сохраняются salted hash;
- старый активный код пользователя инвалидируется при создании нового;
- pairing/refresh/code creation имеют отдельные fixed-window rate limits;
- access token короткоживущий и криптографически защищён существующим Identity stack;
- refresh token ротируется и сохраняется только как SHA-256;
- повторная параллельная ротация защищена условным обновлением хеша;
- watch principal имеет отдельные claims и не может вызывать management endpoints;
- владение всегда выводится из аутентифицированного principal;
- другой пользователь не видит и не отзывает чужое устройство;
- полные коды и токены не попадают в структурные логи;
- password security-stamp change инвалидирует watch credentials.

## Конфигурация

Секция `WatchPairing` задаёт lifetime кода, access/refresh token и предел попыток.
Значения по умолчанию: 10 минут, 15 минут и 30 дней соответственно. Значения
проверяются при старте приложения.
